# خطة تطوير وتدقيق تطبيق TAJER (تاجِر) | إدارة محلك أسهل

مراجعة شاملة للوضع الراهن وخطة التطوير المستقبلية لنظام إدارة متاجر التجزئة والملابس والأحذية في مصر، مع توثيق المعمارية البرمجية وخريطة الطريق دون المساس بالتصميم الحالي أو حذف أي مكونات قائمة.

---

## مراجعة وتدقيق المشروع الحالي (Current Audit & Review)

> [!IMPORTANT]
> **توضيح تقني جوهري حول لغة وتقنية المشروع (React vs Kotlin):**
> المشروع الحالي هو **تطبيق أندرويد أصلي (Native Android App)** مبني بالكامل بلغة **Kotlin** وأحدث أدوات واجهات المستخدم **Jetpack Compose** و **Material 3**. 
> المشروع **لا يحتوي حالياً على ملفات React أو TypeScript أو Tailwind CSS**؛ حيث تم تأسيسه وبناؤه كبيئة عمل Android Studio / Gradle كاملة.

---

### 1. الصفحات والمكونات المنفذة بالفعل (Existing Pages & Components)

يحتوي التطبيق حالياً على معمارية واجهات كاملة ومتجاوبة تدعم الشاشات المكتبية واللوحية (Desktop Sidebar) والهواتف الذكية (Bottom Nav + Navigation Drawer)، موزعة على 8 صفحات رئيسية:

```
┌────────────────────────────────────────────────────────────────────────┐
│                       تطبيق تاجِر (TAJER) - المعمارية الحالية          │
├────────────────────────────────┬───────────────────────────────────────┤
│ المكونات العامة والملاحة       │ صفحات النظام الرئيسية                 │
├────────────────────────────────┼───────────────────────────────────────┤
│ • TajerSidebar (شريط جانبي)     │ 1. DashboardScreen (الرئيسية)          │
│ • TajerBottomNavBar (ملاحة سفلي)│ 2. ProductsScreen (المنتجات والمخزون) │
│ • ReceiptDialog (إيصال حراري)  │ 3. PosScreen (نقطة البيع والكاشير)    │
│ • VariantSelectorDialog        │ 4. CustomersScreen (العملاء والديون)  │
│ • StatsCard & WeeklySalesChart │ 5. ReturnsScreen (الاستبدال والمرتجع) │
│ • TajerTheme (خط Cairo + RTL)  │ 6. ExpensesScreen (المصروفات)         │
│                                │ 7. ReportsScreen (التقارير والأرباح)  │
│                                │ 8. SettingsScreen (إعدادات المتجر)    │
└────────────────────────────────┴───────────────────────────────────────┘
```

1. **الرئيسية (DashboardScreen):**
   - 4 بطاقات إحصائية رئيسية (مبيعات اليوم، ديون العملاء الآجلة، إجمالي المنتجات والقطع، ونواقص المخزون).
   - مخطط بياني أسبوعي تفاعلي (Weekly Sales Chart) مبني بالـ Canvas يعرض مبيعات آخر 7 أيام بالجنيه المصري.
   - أزرار إجراءات سريعة للوصول المباشر (كاشير، إضافة منتج، تسجيل عميل، إضافة مصروف).
   - جدول أحدث الفواتير والعمليات مع إمكانية النقر لمعاينة الإيصال.

2. **المنتجات والمخزون (ProductsScreen):**
   - عرض المنتجات مقسمة حسب الفئات (ملابس رجالي، حريمي، أطفال، أحذية، إكسسوارات).
   - بطاقات المنتجات مع مؤشرات الأسعار وهامش الربح المتوقع.
   - مصفوفة الألوان والمقاسات التفصيلية (Variants Breakdown) برصيد كل توليفة ومؤشرات التنبيه للنواقص.
   - شريط بحث بالاسم والباركود والـ SKU، مع فلتر مخصص لنواقص المخزون فقط.
   - حوار إضافة وتعديل المنتجات (`AddEditProductDialog`) وتوليد المتغيرات ديناميكياً.

3. **نقطة البيع والكاشير (PosScreen):**
   - واجهة كاشير مرنة (شاشة مقسمة للأجهزة اللوحية، وقائمة سفلية للهواتف).
   - حوار اختيار اللون والمقاس وتحديد الكمية (`VariantSelectorDialog`).
   - سلة مبيعات تفاعلية لحساب الإجمالي الفرعي، الخصم المالي، وتحديد العميل.
   - وسائل دفع مصرية كاملة: **كاش، فودافون كاش، إنستاباي (InstaPay)، فيزا وماستركارد، وآجل**.
   - حساب المدفوع والباقي/الآجل آلياً.
   - إيصال حراري إلكتروني عربي واقعي (`ReceiptDialog`) يحتوي على الباركود وسياسة المتجر مع أزرار للطباعة والمشاركة.

4. **العملاء والآجل (CustomersScreen):**
   - دليل العملاء مع بيانات الاتصال والعنوان وإجمالي المشتريات.
   - تمييز أرصدة الديون المستحقة باللون التحذيري.
   - حوار سداد دفعة من الحساب الآجل (`RecordPaymentDialog`) وتحديث الرصيد فوراً.
   - كشف حساب وسجل تاريخي بالمدفوعات لكل عميل (`CustomerLedgerDialog`).
   - حوار إضافة عميل جديد (`AddCustomerDialog`).

5. **الاستبدال والمرتجعات (ReturnsScreen):**
   - الاستعلام برقم الفاتورة الأصلية أو هاتف العميل.
   - عرض بنود الفاتورة واختيار الصنف وتحديد سبب الإرجاع/الاستبدال.
   - إعادة القطعة المسترجعة إلى رصيد المخزن تلقائياً وتوثيق الإيصال المالي.

6. **المصروفات (ExpensesScreen):**
   - بطاقة إجمالي المصروفات الشهرية.
   - تصنيفات المصروفات التشغيلية (إيجار، كهرباء، رواتب، شحن وبضاعة، ضيافة، تسويق).
   - حوار تسجيل مصروف جديد وحذف المصروفات.

7. **التقارير والأرباح (ReportsScreen):**
   - حساب قائمة الدخل المبسطة: المبيعات، تكلفة البضاعة المباعة (COGS)، مجمل الربح، المصروفات، و**صافي الربح النهائي**.
   - حصص وسائل الدفع بنسب مئوية وأشرطة تقدم بيانية.
   - قائمة المنتجات الأكثر طلباً ومبيعاً.

8. **إعدادات المتجر (SettingsScreen):**
   - تعديل بيانات المنشأة (الاسم، الفرع، الهاتف، السجل الضريبي).
   - تخصيص سياسة الاسترجاع ورسالة الشكر المطبوعة على الفاتورة.
   - زر استعادة وتصفير البيانات التجريبية الافتراضية بنقرة واحدة.

### 2. تدقيق الوظائف الحقيقية مقابل البيانات التجريبية

| الخاصية / الوظيفة | نوع التنفيذ الحالي | التفاصيل |
| :--- | :--- | :--- |
| **منطق الخصم وإتمام البيع** | **حقيقي (In-Memory)** | يحسب القيم الرياضية، يخصم رصيد المقاس واللون من المخزن، ويسجل الفاتورة في الذاكرة. |
| **إدارة ديون العملاء وسدادها** | **حقيقي (In-Memory)** | يضيف الديون على العميل، ويسجل دفعات السداد ويخصمها من الرصيد فورياً. |
| **الاسترجاع وإعادة المخزون** | **حقيقي (In-Memory)** | يبحث عن الفاتورة، ويعيد الكمية المسترجعة لرصيد القطعة بالمخزن. |
| **توليد الإيصال الحراري** | **حقيقي (In-Memory)** | يولد إيصالاً كاملاً بتفاصيل الفاتورة والباركود والمبالغ. |
| **طباعة الإيصال عبر البلوتوث/USB** | **محاكاة (Simulation)** | يُظهر إشعاراً بنجاح إرسال الأمر للطابعة (يحتاج ربط Bluetooth ESC/POS للطباعة الفعلية). |
| **البيانات الأولية للمنتجات** | **تجريبية (Seed Data)** | مشبعة بـ 8 أصناف ملابس وأحذية مصرية واقعية تبدأ بها التطبيق. |
| **قاعدة البيانات والتخزين** | **ذاكرة محلية (StateFlow)** | تظل البيانات طوال جلسة التطبيق، لكنها لا تُحفظ في قاعدة بيانات سحابية (Supabase) بعد. |

### 3. هل يحتوي المشروع على ملفات React و TypeScript؟

- **الإجابة الدقيقة:** **لا**، المشروع الحالي أندرويد أصلي (Kotlin + Jetpack Compose).
- إذا كنت ترغب مستقبلاً في بناء نسخة Web موازية بتقنية React / TypeScript / Tailwind CSS، يمكن تأسيس مشروع ويب منفصل يشارك نفس نماذج البيانات، ولكن تطبيقك الحالي هو تطبيق أندرويد حقيقي كامل وجاهز للتشغيل والتصدير.

### 4. طريقة تصدير المشروع بالكامل إلى GitHub

يمكنك تصدير المشروع إلى GitHub بأحد الخيارين التاليين:

#### الخيار الأول: التصدير التلقائي المباشر من واجهة AI Studio (الأسهل والأسرع)
1. من الزاوية العلوية أو قائمة الإعدادات (Settings / Project Menu) في واجهة Google AI Studio Build.
2. اضغط على خيار **"Push to GitHub"** أو **"Export to GitHub"**.
3. قم بتسجيل الدخول بحساب GitHub الخاص بك وتحديد اسم المستودع (Repository Name).
4. سيتم رفع كافة ملفات كود Kotlin والموارد (`res`) وملفات الـ Gradle تلقائياً.

#### الخيار الثاني: التصدير اليدوي عبر تنزيل ملف الـ ZIP
1. اضغط على أيقونة الإعدادات واختر **"Download as ZIP"** لتنزيل مجلد المشروع لجهازك.
2. فك الضغط عن الملف وافتح سطر الأوامر (Terminal) داخل المجلد ثم نفذ الأوامر التالية:
   ```bash
   git init
   git add .
   git commit -m "Initial commit: TAJER Retail Management SaaS"
   git branch -M main
   git remote add origin https://github.com/YOUR_USERNAME/tajer-retail-app.git
   git push -u origin main
   ```
3. افتح المشروع مباشرة عبر **Android Studio** ليعمل معك بسلاسة تامة.

## خطة التطوير المستقبلية (Implementation Roadmap)

### المرحلة 1: الحفاظ على الوضع الحالي وتأكيد الاستقرار (المرحلة الحالية)
- تثبيت كافة الشاشات والواجهات والمكونات الحالية دون أي حذف أو إعادة بناء.
- الحفاظ التام على تصميم الواجهة ونظام الألوان (الأخضر الزمردي والذهب الدافئ) وخط Cairo.

### المرحلة 2: ربط قاعدة البيانات السحابية (Supabase / Firestore)
- ربط معمارية الـ Repository الحالية مع Supabase Database عبر Supabase Kotlin SDK أو REST API.
- مزامنة المنتجات والأسعار والعملاء سحابياً في الوقت الفعلي (Real-time sync).

### المرحلة 3: العتاد والاتصال بالطابعات (Hardware Integration)
- إضافة دعم طابعات الإيصالات الحرارية عبر البلوتوث (ESC/POS Thermal Bluetooth Printers).
- دعم قارئ الباركود عبر كاميرا الهاتف باستخدام Google ML Kit Barcode Scanning.
